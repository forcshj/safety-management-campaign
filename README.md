# 임베딩 · 프리필 시연 도구

기존 캠페인 페이지는 유지하고 `poc/` 경로에 시연 도구를 추가했습니다.

## 실행

Node.js 20 이상에서 `node tools/serve.js` (또는 `npm start`) 후 http://127.0.0.1:4173/poc/ 로 접속합니다. 별도 패키지 설치는 필요 없습니다. HTML 파일을 더블클릭하면 설정 파일을 읽을 수 없으므로 HTTP로 접속하세요.

GitHub Pages가 저장소 루트에서 서비스되고 있다면 `/safety-management-campaign/poc/`에서도 동작합니다. 저장소의 Settings → Pages에서 배포 원본을 확인하세요. 별도의 Sites 호스팅은 만들지 않았습니다.

## 시연 순서

1. 시나리오 선택 → 회사 ID·템플릿 ID 확인.
2. 프리필 값 입력 또는 가상 샘플 채우기. 전송 체크를 해제하면 해당 필드는 전송하지 않습니다.
3. 필요하면 수신자 설정에 JSON 배열 입력. 단계 이름·인증 방식은 해당 템플릿 워크플로와 일치해야 합니다. 기본값 `[]`는 템플릿 설정을 사용합니다.
4. 전송 데이터 확인 → 현재 화면 또는 새 창으로 실행 → eformsign 로그인.
5. SDK 성공 콜백의 필드를 입력 화면에 반영합니다. 처리 성공이 전체 워크플로의 최종 완료를 뜻하지는 않습니다. 최종 상태와 다운로드는 완료 문서함에서 확인하세요.

## 설정 변경

- 현재 브라우저: 회사·템플릿 ID와 필드 ID를 수정하고 **설정 저장**. 입력한 프리필 값, 로그인 ID, 수신자 정보는 저장하지 않습니다.
- 다른 PC: **내보내기** → 다른 PC에서 **가져오기** → **설정 저장**.
- 저장소 기본값: `poc/config.json` 수정 후 GitHub에 반영. 기존 브라우저 저장값이 우선하므로 **기본 설정 복원**을 누르면 새 기본값을 읽을 수 있습니다.
- 시나리오 추가/이름 변경: `config.json`의 `scenarios` 배열에 고유 `id`, `label`, `templateId`, `fields`를 추가합니다.
- 필드 항목은 `{ "id": "실제 템플릿 필드 ID", "value": "", "enabled": true }` 형식입니다. 내보내기 시 입력값은 항상 비웁니다. 파일에는 비밀키와 실제 개인정보를 넣지 마세요.

기존 `3-1`, `3-3`, `3-5`, `3-7`의 입력 필드 ID를 가져왔고 7개 시나리오를 제공합니다. 기존 파일에서 APW 법인 대표자 템플릿 ID가 서로 달라 **3-1.html의 TEMPLATE_MAP** 값을 기준으로 통일했습니다. 실제 사용 가능한 템플릿이 다르면 화면에서 교체하세요. 날짜·동의 등의 값 형식은 각 템플릿에 맞춰 입력하세요.

## 인증과 검증 범위

기존 HTML의 API 키·시크릿은 이 저장소로 가져오지 않았습니다. 기본 모드는 eformsign 로그인 방식입니다. 원본에 들어 있던 키를 계속 사용하는 경우 계정 관리자가 사용 상태를 확인하고 필요시 교체하세요.

기존의 자동 토큰 발급, REST API 폴링, API 문서 목록·다운로드는 공개 정적 페이지에 인증정보를 넣지 않도록 제외했습니다. 로그인 없는 실행과 API 문서함이 필요하면 인증된 사용자를 확인하는 별도 서버에서 토큰을 발급하도록 추가해야 합니다.

실제 계정 로그인, 템플릿 배포·사용 권한, 수신자 인증, 브라우저 쿠키 정책은 실제 환경에서 확인해야 합니다. iframe 로그인에 제약이 있으면 새 창 실행을 사용하세요. 자동화 검증은 `npm test`로 설정 검사, 전송 데이터 생성, 개인정보 제외를 확인합니다.
